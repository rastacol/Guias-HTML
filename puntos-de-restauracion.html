Punto de Restauración Conversación
Analiza toda la conversación actual y genera un PUNTO DE RESTAURACIÓN compacto.

El punto de restauración es un bloque de texto que, pegado al inicio de una nueva conversación, reconstituye el contexto operacional completo sin necesidad de reexplicar nada.

<contexto_operacional>
- Rol / persona activa: (skill, experto, instrucciones especiales vigentes)
- Objetivo de la sesión: (qué se estaba resolviendo)
- Modo de trabajo: (Auditoría / Exploración / Producción)
</contexto_operacional>

<decisiones_clave>
Lista numerada de decisiones tomadas y acuerdos establecidos.
Para cada decisión: qué se decidió + razón principal.
</decisiones_clave>

<artefactos_producidos>
Lista de entregables generados.
Para cada artefacto: nombre + propósito + estado (borrador / aprobado / pendiente revisión).
</artefactos_producidos>

<estado_actual>
- Última tarea completada:
- Tarea en curso (si aplica):
- Punto exacto donde se pausó:
</estado_actual>

<proximos_pasos>
Lista ordenada de acciones pendientes, con responsable y prioridad si se mencionaron.
</proximos_pasos>

<restricciones_activas>
Reglas, No-Hacer, criterios de calidad o restricciones establecidas que deben mantenerse.
</restricciones_activas>

<instruccion_de_arranque>
Instrucción de 2-3 líneas para activar la continuación en una nueva conversación.
</instruccion_de_arranque>

REGLAS: máximo 800 tokens · sin narrativa · omitir secciones vacías · el bloque debe ser autocontenido

SALIDA: genera el resultado como un archivo punto-restauracion.md descargable usando un bloque de código Markdown con instrucciones para guardarlo, o bien usando la herramienta de creación de archivos si está disponible. El archivo debe contener únicamente el bloque XML del punto de restauración, sin texto adicional.
Punto de Restauración Skills
Analiza toda la conversación actual y genera un PUNTO DE RESTAURACIÓN para la skill que estamos trabajando

<skill_activa>
- Skill: [nombre-skill] — [descripción funcional en 1 línea]
- Modo activo: [modo o fase de operación si la skill tiene modos diferenciados]
- Fuente de verdad vigente: [archivo de referencia activo: SKILL.md / normativa / biblioteca / ninguno]
</skill_activa>

<estado_del_workflow>
- Etapa o paso completado: [nombre o número de la etapa]
- Objeto de trabajo en esta sesión: [qué se estaba procesando — proceso, contenido, documento, caso]
- Insumos procesados: [documentos / datos / artefactos analizados hasta ahora]
- Insumos faltantes: [pendientes de recibir — o "ninguno"]
- Punto exacto de pausa: [sección / criterio / ítem / paso donde se detuvo]
</estado_del_workflow>

<artefactos_y_resultados>
Por cada artefacto producido o resultado acumulado:
- Nombre / identificador | Propósito | Estado: generado / revisado / aprobado / pendiente
- Bugs o errores documentados (si aplica): tipo de error
</artefactos_y_resultados>

<evaluacion_parcial>
[Solo si la skill produce valoración acumulada: semáforo, conteo de hallazgos, etc.]
- Valoración provisional: 🔴 / 🟡 / 🟢
- Acumulado críticos / medios / bajos: N / N / N
- Riesgo o alerta principal identificada hasta ahora:
</evaluacion_parcial>

<reglas_activas_de_la_sesion>
- [Restricción, corrección o excepción que debe mantenerse]
- [Convención de nombrado, criterio de calidad o No-Hacer acordado]
</reglas_activas_de_la_sesion>

<pendientes>
- Etapas / criterios / secciones no recorridos aún
- Verificaciones cruzadas o datos a solicitar al usuario
- Informe / entregable final: generado [nombre-archivo] / pendiente generación
</pendientes>

<instruccion_de_arranque>
"Continuamos la skill [NOMBRE-SKILL]. Íbamos en [etapa / sección / criterio exacto].
[Qué hacer primero al retomar — acción concreta en 1 línea]."
</instruccion_de_arranque>

REGLAS: máximo 600 tokens · sin narrativa · omitir secciones vacías · si un entregable ya fue generado, indicar nombre del archivo · el bloque debe ser autocontenido

SALIDA: genera el resultado como un archivo punto-restauracion-skill.md descargable usando un bloque de código Markdown con instrucciones para guardarlo, o bien usando la herramienta de creación de archivos si está disponible. El archivo debe contener únicamente el bloque XML del punto de restauración, sin texto adicional.
